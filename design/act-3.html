Act 3 — Canvas Knows What You’ve Built

Eight scenes: parallel sessions, background completion, session review, commit, exit, project overview, stats, and history.

Job to be done: Work across parallel sessions without conflicts, stay informed without interruption, and accumulate project-level memory that persists across sessions.

You’ve been using Canvas for a while now. The terminal is comfortable. The viewer is useful. But you’re starting to push harder — multiple sessions on the same project, long-running tasks in the background, context you need to remember across days. This is where Canvas transitions from utility to infrastructure. The conceptual shift: sessions stop being ephemeral terminal instances and become meaningful units of work with identity, history, and memory. The CLI shows you session_a3f2b1c · 2 days ago. That’s not memory. That’s an ID. Canvas turns IDs into stories.

This act has three sub-arcs: Parallel work — running multiple sessions without conflicts. Staying informed — knowing what happened without hunting for it. Project memory — accumulating understanding that persists.

Scene 3.1 — Start a Second Session

You have “Auth module” running (28m, amber dot). You click “+” on the project row. Because a session is already running, Canvas shows a small popover with two choices: “Same branch” (share the working directory with the running session) or “New worktree” (isolated copy — no file conflicts). You pick “New worktree.” A new session appears in the sidebar as “New session” with an amber dot. The terminal shows the Amplifier banner confirming worktree isolation. You type your first prompt: “add dark mode support.” The sidebar renames from “New session” to “Dark mode.”

Two product decisions land here. First: worktree isolation is offered as a choice, not forced. If you’re just starting a quick follow-up session that doesn’t conflict, “Same branch” is simpler. If you’re doing parallel work, “New worktree” gives you true isolation — each session gets its own branch and working directory. Second: the session is unnamed until your first prompt. “New session” becomes “Dark mode” because the name comes from your intent, not from Canvas guessing.

Scene 3.2 — Session Completes

An hour later. You’re deep in the Dark mode session when a toast notification appears at the bottom of the screen — “Auth module just finished.” In the sidebar, the Auth module’s amber dot becomes a green checkmark badge. Its status reads “done · 1h 12m.” You’re not pulled away from your current work. The notification is informational, not interruptive.

This is “respect attention” made concrete. A background session completed. Canvas tells you — once, subtly — and then gets out of the way. The sidebar’s state change is persistent (you can glance at it anytime) but the toast is transient (it doesn’t demand action). This is the answer to “did something happen while I wasn’t looking?” — the question that Outcome 2 says users should never need to ask.

Scene 3.3 — Review Completed Session

You click “Auth module” in the sidebar. The terminal switches to that session’s history. The right panel opens to the SUMMARY tab — a structured summary of everything that happened. At the top: a one-sentence description (“Built the session panel sidebar with live status indicators, duration counters, and worktree badges”), test status (14/14 passing), and session stats (1h 12m, 8 prompts, 142k tokens). Below: collapsible sections for Prompt History, Key Moments, and Possible Next Steps.

This is session recall — the ability to understand what a session did without scrolling through terminal history. The prompt history gives you the narrative arc. The key moments give you the turning points. The next steps give you continuity. A session is no longer something that happened and vanished. It’s a chapter you can re-read.

Scene 3.4 — Commit the Changes

You commit from the terminal: git add -A && git commit, git push origin main, gh pr create. Canvas doesn’t interfere — this is your CLI workflow. But the right panel’s SUMMARY tab updates to surface the result: “PR #47 opened · no conflicts,” CI status (green dot, 14/14 checks), commit hash, file diff summary. A “View PR #47 →” link in amber goes to GitHub. Files changed are listed with line counts.

Canvas is additive, not replacement. You commit the way you’ve always committed. But Canvas shows you what you committed in a structured view — no need to open GitHub to check CI status, no need to remember which files changed. The SUMMARY tab is the “receipt” for your work. The CLI does the action. Canvas shows the result.

Scene 3.5 — Exit Session

You type exit. Amplifier exits. The shell prompt returns. The sidebar updates: the completed session is gone from the active list, replaced by a “New session” slot on main, ready for the next task. The Dark mode session is still running in its worktree. The terminal shows helpful hints: amplifier to start new, amplifier session resume to resume. The worktree is preserved — nothing was lost.

Exiting a session doesn’t feel like closing something — it feels like completing something. The session’s work persists in git, in the PR, in the session history. The “New session” slot signals readiness without pressure. You could start another session right now, or close Canvas entirely. The state is durable.
