Act 1 — Getting Started
Get from zero to a running session with minimum friction
1.1
Welcome
Match

Storyboard says

  • Narrow sidebar: "Projects" with + button
  • "No projects yet" placeholder
  • Warm off-white main area
  • Centered welcome: "Welcome to Canvas — Your workspace..."

App actually has

Verdict: Match. Core elements identical. Header buttons (Layout, Notifications, Settings) exist in the app but aren't described in the storyboard — they're chrome, not story beats, so this is fine.

Act 2 — Your First Session
Discover that Canvas adds value on top of the CLI — the viewer earns its place
2.1
Reading the Codebase
Drift

Storyboard says

  • Terminal: user types prompt, sees tool calls, gets summary
  • No right panel — viewer stays hidden
  • Full-width terminal

App actually has

  • Terminal: works as described
  • Viewer auto-opens when session selected
  • Selecting a session triggers openViewer()
Drift: Significant. The storyboard's core principle is "viewer stays hidden until it earns its place." The app auto-opens the viewer on session select, violating progressive disclosure. Decision needed: should viewer auto-open or start hidden?
2.2
Reviewing the Vision
Drift

Storyboard says

  • Viewer slides in for the first time when Amplifier opens a file
  • "Opened by Amplifier" provenance label
  • FILES tab active, one tab: VISION.md
  • Rendered markdown

App actually has

  • Viewer panel exists with FILES tab
  • File rendering works (code, markdown, images)
  • File activity badges: read (green), write (orange), etc.
  • No "Opened by Amplifier" provenance label
  • __canvasOpenFile() exists for programmatic file opening
Drift: Moderate. The file viewing infra exists but the provenance labeling ("Opened by Amplifier" vs "Opened by you") isn't built. File activity badges are a different approach to the same concept. Decision needed: provenance labels or activity badges?

App Preview
Drift

App actually has

Act 3 — Canvas Knows What You've Built
Parallel sessions, staying informed, project-level memory
3.1
Start a Second Session
Not Built

Storyboard says

  • Start a second session on same project
  • Canvas creates a git worktree automatically
  • Worktree badge on session in sidebar
  • "Isolated from session 1" confirmation
  • Both sessions work independently, zero conflicts

App actually has

  • + button spawns a new session (single PTY)

Not built. Worktree-based session isolation is the core feature of this scene. The + button exists but doesn't create worktrees. This is a significant architectural feature. Needs building
