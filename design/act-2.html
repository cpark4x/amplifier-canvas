Act 2 — Your First Session

Five scenes: the AI becomes your co-pilot. The viewer earns its place.

Job to be done: Discover that Canvas adds value on top of the CLI, without ever getting in the way. The viewer earns its place.
You’re in the terminal. This feels familiar — it’s just Amplifier. But you’re inside Canvas, and over the next few minutes, the right panel is going to reveal itself. Not all at once. Not because you asked for it. Because the work creates artifacts worth seeing. The viewer doesn’t exist until it has something to show.

Scene 2.1 — First Prompt

You type: “help me understand this codebase.” Amplifier reads four files, listed as tool calls in the terminal. A green checkmark: “✓ 4 files read.” Amplifier responds with a summary. The terminal occupies the full width. There is no right panel. There’s nothing to show yet.

This is the restraint that defines Canvas. A lesser product would open a file viewer the moment Amplifier reads a file. Canvas doesn’t. The viewer has no content worth displaying — so it stays hidden. The terminal gets all the space. Canvas won’t waste your screen real estate on empty panels.

Scene 2.2 — The Viewer Earns Its Place

You type: “let’s review the vision together.” Amplifier reads VISION.md and opens it in the viewer — the right panel slides in for the first time. The FILES tab is active. One file tab: VISION.md with a green activity dot (read). The terminal narrates: “Opening VISION.md in viewer →.”

The viewer appeared because Amplifier decided you needed to see this file, not just hear about it. The panel didn’t exist 10 seconds ago. It earned its place. The activity badge (green dot = read) tells you the operation type at a glance — no labels, no provenance text, just signal.

Scene 2.3 — Working with Files

OUTCOMES.md is now open alongside VISION.md. Two file tabs in the secondary row, each with a green activity dot (read). You can switch between them. The file browser has closed — it gets out of the way once you’ve made your selection.

The multi-file experience is established with zero explanation. Tabs work like tabs. Activity badges update in real time as Amplifier reads and writes — green dots for reads, orange for writes, blue for edits. The color tells you what happened without hovering or clicking.

Scene 2.4 — Side-by-Side

You ask Amplifier to scaffold a Dashboard component. It reads App.tsx, writes a new Dashboard.tsx, and edits App.tsx to wire it in. The terminal shows tool calls and responses. The viewer updates in real time — Dashboard.tsx appears with an orange activity dot (write), App.tsx shows a blue dot (edit). You’re watching the AI work.

This is the workflow loop that converts skeptics. You type a prompt. Amplifier works. Files appear in the viewer as they’re created. The activity dots tell the story — green means read, orange means written, blue means edited. Terminal and viewer are two views of the same work happening in real time.

Scene 2.5 — App Preview

You run npm run dev. The dev server starts: “✓ Ready in 847ms.” The APP tab activates automatically, showing a live preview of your running application at localhost:3000 — embedded right in the panel. No browser tab. No alt-tabbing.

This is the moment Canvas stops being “nice to have” and becomes essential. The app preview collapses an entire workflow — terminal, browser, resize windows, check output — into a single glance. You made changes in the terminal. You see them in the panel. The feedback loop is instant and contained.
