Act 4 — Project Intelligence

Canvas understands your project — surfacing insights, tracking progress, keeping history.

Job to be done: Step back from individual sessions to see the big picture. Canvas synthesizes everything into project-level understanding — where things stand, what patterns are emerging, what happened when.

You’ve been through multiple sessions now. Auth module is committed and merged. Dark mode is running in a worktree. You’ve explored the codebase, built scaffolding, shipped features. But there’s no place where all of that comes together into a coherent picture. The CLI gives you amplifier session list — a flat dump of IDs and timestamps. Canvas gives you project intelligence: an AI-synthesized overview, aggregate stats with LLM-generated insights, and a complete session history where every piece of work has a name, a summary, and a way back in.

This act has three scenes: Project overview — the AI assessment of where you are. Stats — numbers and patterns the model can see but you can’t. History — the complete record, proving nothing is ever lost.

Scene 4.1 — Project Overview

Primary path (natural): You just exited your last session at the end of Act 3. The shell prompt returned, but instead of staring at an idle terminal, the main area naturally transitions to the project overview. When you’re between sessions — no active session selected — the project view is the default. It appears without you asking for it. The overview replaces the empty terminal because between sessions is when the project-level view matters most.

Secondary path (intentional): The project name row (“CANVAS-APP”) in the sidebar is not a static label. It has a subtle background highlight on hover, a pointer cursor — it’s obviously clickable. At any point — even mid-session — you can click the project name to jump to this view. The sidebar shows the project row in an active state with a left-accent border, mirroring how active sessions look.

The view itself: default tab is OVERVIEW. At the top, an AI assessment banner — “✶ AI assessment: On track — 1 of 3 outcomes in progress · 3 sessions completed · last activity today.” Below: the project heading (“Amplifier-Canvas”), its one-line vision, and a structured outcomes list from OUTCOMES.md with status badges and AI-generated evidence.

Discoverability is solved two ways. First, you stumble into it naturally — when no session is active, the project overview fills the void. This means every user sees it eventually, without documentation or onboarding. Second, you can get there intentionally — the project name row is a real interactive element, not a category header. Between these two paths, no user should ever wonder “how do I see my project?” This is project memory made visible. Canvas isn’t just tracking sessions — it’s tracking the project. The AI assessment synthesizes across all sessions. The outcomes list connects daily work back to the goals that matter.

Scene 4.2 — Project Stats

You tap the STATS tab. A 2×2 grid shows aggregate numbers: 8 sessions, 12h 34m total time, 847k tokens, 156 files touched. Below: an LLM-generated insights section — four observations the AI extracted from session patterns. “Velocity: Sessions are getting shorter — avg 1h 45m early, now 28m. You’re in a refinement phase.” “Alignment: Outcome 2 (faster debugging) has never been addressed across 8 sessions. This may become a gap.” “Efficiency: Token efficiency improving — 18k tokens per file change early, now 12k.” “Risk: File viewer has been in progress for 3 sessions without completing.” Below the insights: per-session breakdowns.

The stats tab turns invisible work into visible patterns. No developer tracks their token efficiency across sessions. No one notices that an outcome hasn’t been touched in 8 sessions. Canvas sees what you can’t, because it has the data and the model to interpret it. The LLM-generated insights are clearly labeled (✶ spark icon, “LLM-generated” badge, “Regenerate” action) — Canvas never pretends AI conclusions are facts.

Scene 4.3 — Session History

You tap the HISTORY tab. At the top: the currently running session (Dark mode, amber dot, 1h 22m, “View →”). Below a “History” label: every completed session — Auth module (today, 1h 12m, “Built session panel with live status indicators,” PR #47 linked), Explore codebase (today, 28m), then older sessions going back days. Each has a title auto-derived from its first prompt, a one-line summary, duration, and a “Resume →” action. At the bottom: “+ 3 more sessions.”

This is the final scene because it delivers the thesis: nothing is ever lost. Every session you’ve run lives here with a meaningful name, a summary, and a way back in. “Auth module” isn’t session_a3f2b1c — it’s a piece of work you can describe, find, and resume. This is the project memory that the CLI never had. The story ends with accumulation — your project is richer for having used Canvas.
